## 3. Achados do dia

### 3.1 Loop infinito de render no `SelectSheet` — defeito real, não só de teste

O componente sincronizava o estado interno a partir de props dentro de um `useEffect` sem guarda
de igualdade. Com um array inline (`values={[...]}` — comum em JSX), a referência nova a cada
render realimentava o efeito, que disparava `setState`, que re-renderizava. **Um chamador
qualquer que passasse um array inline quebraria o app em produção.**

**Correção:** atualização funcional que devolve o estado anterior quando o conteúdo é equivalente.
O comentário no código registra o motivo, para que a guarda não seja removida por engano.

### 3.2 Duas falhas de teste pré-existentes

Ambas já falhavam no código original (confirmado com `git stash` sobre `HEAD`), introduzidas por
commits posteriores à evidência de validação de 01/09/2026:

| Falha | Causa | Correção |
|---|---|---|
| `privacyAccess.test.js` — *"token without a valid expiration"* | `74b3035` passou a exigir token JWT e a gravar um envelope `{token, exp, user}`; o teste usava um token opaco e afirmava *"persists only the token"* | Duplo de teste passou a produzir JWT real; asserções atualizadas para o contrato vigente; **`docs/architecture.md` corrigido** (dizía *"Only the token is persisted"*) |
| `us1-offline-flow.test.js` — *"Unable to find… Seizure date and time"* | `ae293e1` substituiu o campo ISO por seletores nativos; o teste ainda fazia `fireEvent.changeText` | Telas passaram a aceitar `initialOccurredAt` / `initialRecordedAt` (mesmo padrão de `CalendarScreen`) |

### 3.3 Regressão de lint pré-existente

`mobile/app/(patient)/index.js` tinha um `catch {}` vazio (commit `40c2cd9`) que quebrava
`npm run lint`. Corrigido com comentário explicativo.
